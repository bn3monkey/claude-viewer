1. 배경과 목표

현재(1.0.1) 뷰어는 탭 목록을 하나만 가진다. 한 프로젝트에서 설계 문서(docx·pdf·html)를 왼쪽에 두고 Notion 에 정리하다가, 다른 프로젝트의 세션이 끝나 그쪽으로 넘어가 설계 문서를 읽고 지시를 내린 뒤 다시 돌아오면, 보고 있던 탭들이 섞이거나 닫혀 있어 작업 맥락을 매번 다시 만들어야 한다.

v1.1.0 의 목표는 "프로젝트를 클릭하면 그 프로젝트에서 보던 화면이 그대로 돌아온다" 는 것이다. 이를 위해 아래 다섯 기능을 추가하고, 터미널 붙여넣기 버그 하나를 함께 고친다.

ID기능크기의존

2. 용어

용어뜻
뷰어 (Viewer)화면 오른쪽 ⑤ File Viewer 영역 전체. 1.0.1 에서 탭 바 하나와 본문 하나로 되어 있다.
분할 (Pane)뷰어 안에서 탭 바 + 본문을 하나씩 가진 독립 영역. 최대 2개(왼쪽 · 오른쪽). 분할이 하나면 그것이 "왼쪽" 이다.
탭 (Tab)파일(경로+모드), diff, 터미널, 인터넷 페이지 하나. 어느 한 분할에만 속한다.
포커스된 분할사용자가 마지막으로 클릭(탭 바 또는 본문)한 분할. 트리에서 파일을 열면 여기로 들어간다.
레이아웃 (Layout)분할 목록(1~2개) + 각 분할의 탭과 활성 탭 + 포커스된 분할 + 분할 비율 + 세션 대화창 숨김 여부. 프로젝트 하나에 레이아웃 하나.
세션 대화창가운데 열의 ④ Session UI(SessionPanel). 사용량 바·대화·입력창을 포함한 열 전체를 가리킨다.
현재 프로젝트useProjectVM.selection.root. 프로젝트 행 또는 그 아래 세션을 고르면 바뀐다. 아무것도 안 골랐으면 "프로젝트 없음" 레이아웃(키 "")을 쓴다.
세션 출처 열기대화 쪽에서 비롯된 열기. ① AI 응답의 <viewer open=…/> 지시문(백엔드 이벤트 viewer://open), ② 대화 말풍선 안 링크 클릭(activateLink), ③ 권한 카드·도구 결과 등 세션 패널 안에서 눌러 여는 파일.

3. 기능 요구사항

F1 세션 대화창 숨김 / 보이기 작음

앱은 세 열로 되어 있다: ① Projects & Sessions + 트리, ② 세션 대화창(④ Session UI), ③ 파일 뷰어. 문서를 읽거나 Notion 에 정리할 때는 대화창이 자리를 차지하므로 가운데 세션 대화창을 숨기고 뷰어가 그 자리를 쓰게 한다. 숨김 여부는 프로젝트별로 기억한다(F5 레이아웃의 일부).

1.1 토글 위치 — 항상 떠 있는 작은 띠

세션 대화창의 왼쪽 가장자리(트리 열과 대화창 사이)에 폭 12px 의 세로 띠를 상시 둔다. 이 띠가 유일한 토글이다. 보이는 상태에서 누르면 접히고, 접힌 상태에서 누르면 펴진다. 띠는 접혀도 같은 자리·같은 크기로 남으므로 되돌릴 곳을 찾을 필요가 없다.

  • 크기: 폭 12px, 높이는 열 전체. 마우스로 누를 수 있을 만큼만 두고 화면을 거의 차지하지 않는다. 클릭 판정은 띠 전체.
  • 모양: 평소엔 배경과 거의 같은 색(--bg2)에 세로 가운데 작은 꺾쇠 하나만 보인다. 펼친 상태는 ‹(누르면 접힘), 접힌 상태는 ›(누르면 펴짐). 마우스를 올리면 배경이 --bg3 로 밝아지고 툴팁 "세션 대화창 숨기기 / 보이기" 를 보인다.
  • 알림 점: 접힌 동안 선택된 세션이 진행 중이거나 권한 질문이 기다리면 꺾쇠 아래에 6px 빨간 점.
  • 리사이즈 핸들과 분리: 띠는 클릭 전용이고 끌어서 너비를 바꾸지 않는다. 대화창 ↔ 뷰어 사이의 기존 리사이즈 핸들은 그대로이며, 접힌 동안에만 사라진다. 띠를 대화창 왼쪽에 두는 이유는 오른쪽 핸들·F2 분할 핸들과 겹치거나 헷갈리지 않게 하기 위해서다.

1.2 동작

  • 띠를 누르면 useViewerVM.toggleSession() 을 부른다. 상태는 현재 프로젝트 레이아웃의 sessionHidden 에 저장되며, 프로젝트를 바꾸면 그 프로젝트의 값이 적용된다(F5).
  • 구현: 메인 PanelGroup 에서 세션 Panel 앞에 띠 컴포넌트(SessionToggle)를 고정 폭 요소로 넣고, 세션 Panel 은 collapsible collapsedSize={0} 로 두어 ref 의 collapse()/expand() 로 제어한다. 펼칠 때는 숨기기 전 너비(layout-main 의 저장값)로 돌아온다.
  • 세션 패널은 숨겨도 언마운트하지 않는다. 대화 스트림·입력 중인 초안·스크롤 위치가 그대로 남아야 하고, 권한 질문 카드도 계속 쌓여야 한다.
  • 자동으로 보이기: Projects & Sessions 에서 세션 행을 클릭하면(그 프로젝트가 숨김 상태여도) 대화창을 보인다 — 세션을 고른다는 것은 보겠다는 뜻이기 때문. 새 활성화 세션 생성·재개도 같다. 프로젝트 행 클릭은 저장된 숨김 상태를 그대로 따른다.
  • 프로젝트가 선택되지 않은 상태("" 레이아웃)에서도 토글은 동작하며 그 값은 "" 에 저장된다.
  • 단축키는 v1.1.0 에서 두지 않는다(터미널 탭이 포커스를 가질 때 셸로 보내는 키와 충돌 여지, §9 Q11).
수용 기준. ① A 프로젝트에서 띠를 누르면 대화창이 접히고 뷰어가 가운데까지 넓어지며, 띠는 같은 자리에서 › 로 바뀐다. ② 띠를 다시 누르면 접기 전 너비로 펴진다. ③ B 프로젝트를 클릭하면 B 의 상태(기본 보임)가 적용되고, A 로 돌아오면 다시 접혀 있다. ④ 앱을 다시 켜도 A 는 접힘, B 는 보임이다. ⑤ 접힌 채 A 의 세션 행을 클릭하면 대화창이 나타나고 A 의 저장값은 "보임" 으로 바뀐다. ⑥ 접힌 동안 세션이 돌고 있으면 띠에 빨간 점이 보이고, 펴면 입력 중이던 초안이 그대로 있다.

2.1 드래그 시작

  • 탭은 HTML5 Drag & Drop(draggable)으로 끈다. tauri.conf.json 의 dragDropEnabled: false 가 이미 있어 WebView2 에서 HTML5 DnD 가 동작한다(트리 패널의 react-arborist 가 같은 경로를 쓴다).
  • dataTransfer 타입 application/x-claude-viewer-tab 에 { pane, key } 를 JSON 으로 담는다. 다른 타입(파일 등)은 드롭 대상으로 받지 않는다.
  • 드래그 중에는 전역 dragging 상태를 올려 모든 분할 본문 위에 드롭 영역 오버레이를 띄운다. 인터넷 탭의 자식 웹뷰는 이 동안 숨긴다(§5 참조, 웹뷰가 오버레이를 덮기 때문).
  • Esc 또는 밖에 놓으면 취소.

2.2 드롭 대상과 결과

현재 분할 수놓은 곳결과
1개본문 왼쪽 가장자리 영역왼쪽에 새 분할을 만들고 탭을 옮긴다. 기존 분할은 오른쪽이 된다.
본문 오른쪽 가장자리 영역오른쪽에 새 분할을 만들고 탭을 옮긴다. 기존 분할은 왼쪽이 된다.
본문 가운데아무 일 없음.
같은 탭 바의 다른 위치탭 순서 바꾸기(놓은 자리에 삽입).
2개어느 분할이든 본문 왼쪽 가장자리탭을 왼쪽 분할로 옮긴다(세 번째 분할은 만들지 않는다).
어느 분할이든 본문 오른쪽 가장자리탭을 오른쪽 분할로 옮긴다.
다른 분할의 본문 가운데 또는 탭 바그 분할로 옮긴다. 탭 바에 놓으면 그 자리에, 본문에 놓으면 맨 뒤에 삽입.
같은 분할의 탭 바순서 바꾸기.
  • 옮겨진 탭은 목적지 분할에서 활성 탭이 되고, 목적지 분할이 포커스를 얻는다.
  • 탭 키(mode|path 등)는 뷰어 전체에서 유일하다. 목적지 분할에 같은 키의 탭이 이미 있으면 끌어온 쪽을 닫고 기존 탭을 활성화한다(합침). 같은 파일을 두 분할에 동시에 띄우는 것은 지원하지 않는다 — 편집 초안·스크롤 위치가 탭 키로 저장되기 때문(viewerBuffers.ts).
  • 출발 분할에서 활성 탭이 빠져나가면 이웃 탭(기존 close 와 같은 규칙)이 활성이 된다.
  • 출발 분할의 탭이 0개가 되고 분할이 둘이면 빈 분할은 자동으로 닫혀 단일 화면으로 돌아간다. 분할이 하나뿐이면 빈 채로 남아 "트리에서 파일을 선택하면…" 안내를 보인다.

2.3 분할 닫기 버튼

  • 분할이 둘일 때 각 분할의 탭 바 맨 오른쪽 끝에 × 버튼(.tabs .close)을 둔다. 분할이 하나면 보이지 않는다.
  • 누르면 그 분할의 모든 탭을 닫는다. 저장하지 않은 편집이 있으면 기존 confirmDiscard 로 확인하고, 터미널 탭은 프로세스를 끝내고(closeTerminals), 인터넷 탭은 웹뷰를 없앤다. 취소하면 아무 변화 없음.
  • 남은 분할이 단일 화면이 되고 포커스를 받는다.

2.4 분할 비율과 포커스

  • 두 분할은 react-resizable-panels 가로 PanelGroup 으로 나누고 사이에 resize-h 핸들을 둔다. 비율은 autoSaveId 대신 레이아웃에 저장해 프로젝트별로 기억한다(F5). 기본 50 : 50, 각 분할 최소 20%.
  • 분할 안 어디든 pointerdown 하면 그 분할이 포커스된다. 포커스된 분할의 활성 탭 위에 2px 강조선(--accent), 포커스 없는 분할의 활성 탭은 지금처럼 배경색만.
  • 트리 클릭·우클릭 메뉴·F12·터미널 실행·git diff 등 사용자가 뷰어/트리에서 여는 탭은 포커스된 분할로 들어간다. 세션 출처 열기는 F3.
  • Ctrl+F 찾기 바, 정의 목록(DefinitionPicker), 이미지 맞춤 토글은 분할마다 따로 동작한다. 찾기는 마지막으로 클릭한 분할만 가로챈다(현재의 "마지막 클릭이 이 패널일 때만" 규칙을 분할 단위로).

2.5 탭 우클릭 메뉴 변경

기존 "닫기 / 다른 탭 모두 닫기 / 모든 탭 닫기" 에 아래를 더한다. "모든 탭 닫기" 는 그 분할의 탭만 닫는다.

  • 오른쪽으로 분할 / 왼쪽으로 분할 — 분할이 하나일 때. 드래그 없이 같은 결과.
  • 다른 분할로 이동 — 분할이 둘일 때.
  • 인터넷 탭 열기… — F4. 탭이 하나도 없어도 메뉴가 뜨도록 ContextMenu.Trigger 의 disabled 를 없앤다.
수용 기준. ① 탭 3개인 단일 화면에서 하나를 오른쪽 가장자리에 놓으면 왼쪽 2개 · 오른쪽 1개가 되고 오른쪽이 포커스된다. ② 그 상태에서 왼쪽 탭을 오른쪽 탭 바에 놓으면 왼쪽 1개 · 오른쪽 2개. ③ 왼쪽의 마지막 탭을 오른쪽으로 끌면 단일 화면으로 돌아간다. ④ 저장 안 한 편집 탭이 있는 분할의 × 를 누르면 확인창이 뜨고, 취소하면 그대로다. ⑤ 터미널 탭을 다른 분할로 옮겨도 셸 출력과 스크롤백이 유지된다. ⑥ 분할 사이 경계를 끌어 비율을 바꾸고 앱을 다시 켜도 그 비율이다.

F3 세션이 여는 화면은 왼쪽 분할 작음

세션 출처 열기(§2 용어)는 포커스와 무관하게 왼쪽 분할(panes[0])에 들어간다. 분할이 하나면 그것이 왼쪽이다.

  • useViewerVM.open(request, extra) 의 extra 에 target?: "left" | "focused" 를 더한다. 기본은 "focused".
  • "left" 를 넘기는 곳: startViewerEvents 의 viewer://open 처리, 세션 패널 안 Markdown(ChatItem) 의 링크 활성화 경로. Markdown 컴포넌트는 뷰어의 미리보기와 공유되므로 source: "session" | "viewer" prop 으로 구분해 세션 쪽만 왼쪽으로 보낸다.
  • 열린 탭은 왼쪽 분할의 활성 탭이 된다. 포커스된 분할은 바꾸지 않는다 — 사용자가 오른쪽에서 보고 있던 흐름(예: Notion)을 끊지 않기 위함. 같은 키의 탭이 오른쪽 분할에 이미 있으면 새로 만들지 않고 오른쪽에서 활성화만 한다(유일성 규칙 우선).
  • 분할을 새로 만들지는 않는다. 사용자가 분할을 안 썼으면 지금과 똑같이 하나의 화면에 열린다.
수용 기준. ① 오른쪽 분할을 포커스한 채 AI 가 <viewer open="docs/a.md"/> 를 보내면 a.md 는 왼쪽 분할의 활성 탭이 되고 오른쪽 분할의 활성 탭과 포커스는 그대로다. ② 대화 안 링크 클릭도 같다. ③ 뷰어의 Markdown 미리보기 안 링크 클릭은 포커스된 분할에 열린다(기존과 동일).

F4 인터넷 탭 큼

탭 바 우클릭 메뉴의 "인터넷 탭 열기…" 로 URL 을 입력하면 앱 안에 웹 페이지를 띄운다. Notion·GitHub·사내 위키처럼 로그인이 필요한 사이트도 열려야 하므로 Tauri 자식 웹뷰로 구현한다(비교는 §5).

4.1 열기

  • 메뉴 항목 선택 → 기존 askText("인터넷 탭 열기", "URL") 로 입력. 빈 값·취소면 아무 일 없음.
  • 정규화: 앞뒤 공백 제거. 스킴이 없으면 https:// 를 붙인다. http:·https: 외 스킴(file:, tauri:, htmlview:, javascript: …)은 토스트로 거부.
  • 탭은 우클릭한 탭 바가 속한 분할(분할이 없으면 포커스된 분할)의 맨 뒤에 열리고 활성·포커스된다.
  • ViewerMode 에 "web" 을 더한다. ViewerRequest.path 에 URL 을 담는다. 탭 키는 web|<uuid> — 같은 URL 을 여러 탭으로 열 수 있고, 안에서 이동해 URL 이 바뀌어도 키가 변하지 않게.
  • 탭 이름은 페이지 title(웹뷰가 알려 줌), 없으면 호스트명. 접미사 없음, 아이콘으로 Globe 를 앞에 붙인다.

4.2 머리글(vhead)

← 뒤로 · → 앞으로 · ⟳ 새로 고침 · [ URL 입력란 ] · ↗ 외부 브라우저로 열기. 입력란에서 Enter 면 이동, 현재 URL 은 이동할 때마다 갱신. 뒤로/앞으로는 가능할 때만 활성. "읽기 전용" 표시는 없다.

4.3 표시와 숨김

  • 웹뷰는 DOM 이 아니라 창 위에 겹쳐 뜨는 네이티브 뷰다. 프론트의 WebView 컴포넌트가 자기 본문 div 의 위치·크기를 ResizeObserver 와 창 리사이즈로 추적해 백엔드 web_set_bounds 로 보낸다(논리 px, LogicalPosition/LogicalSize).
  • 아래 경우 웹뷰를 숨긴다(web_set_visible(false)): 탭이 비활성 · 그 분할이 다른 프로젝트 레이아웃으로 바뀌어 화면에서 내려감 · 탭 드래그 중 · Radix 다이얼로그/컨텍스트 메뉴/드롭다운이 열려 있는 동안. 마지막 조건은 document.body 에 MutationObserver 하나를 두고 [data-radix-popper-content-wrapper], [role="dialog"] 존재 여부를 보는 전역 훅으로 구현해 개별 컴포넌트를 고치지 않는다.
  • 숨겨도 페이지는 살아 있다(로그인·스크롤 유지). 탭을 닫으면 web_close 로 웹뷰를 없앤다.

4.4 안전 규칙

  • 자식 웹뷰는 원격 URL 전용이며 Tauri IPC 가 주입되지 않는다(dangerousRemoteDomainIpcAccess 를 쓰지 않음). 별도 capability 파일(capabilities/web.json, webviews: ["web-*"])에 권한 없음으로 선언한다.
  • on_navigation 에서 http(s) 외 스킴은 막는다. 새 창 요청(target=_blank)은 같은 웹뷰에서 연다.
  • 쿠키·로컬스토리지는 WebView2 의 앱 사용자 데이터 폴더에 남아 다음 실행에도 로그인이 유지된다(사용자가 원하는 동작). 설정 창에 "인터넷 탭 데이터 지우기" 는 v1.1.0 범위에 넣지 않는다(§10).

4.5 저장·복원

  • SavedTab { mode: "web", path: <현재 URL> } 로 레이아웃에 저장(F5). 복원 때 웹뷰를 다시 만들고 그 URL 을 연다. 뒤로/앞으로 기록은 복원하지 않는다.
  • 저장 시점은 다른 탭과 같다(변경 뒤 300ms). URL 이 바뀔 때마다 탭의 path 를 갱신하므로 자동으로 포함된다.
수용 기준. ① notion.so 를 입력하면 Notion 이 열리고 로그인할 수 있으며, 앱을 다시 켜도 로그인이 유지된 채 같은 페이지가 열린다. ② 인터넷 탭 위에서 우클릭 메뉴·설정 창을 열면 웹뷰가 메뉴를 가리지 않는다. ③ 다른 탭으로 가면 웹뷰가 사라지고 돌아오면 스크롤 위치 그대로 돌아온다. ④ 분할 경계를 끌면 웹뷰가 분할 크기를 즉시 따라간다. ⑤ file:///C:/ 를 입력하면 거부 토스트가 뜬다. ⑥ 페이지 안 링크를 눌러 이동하면 탭 이름과 URL 란이 바뀌고 ← 가 활성화된다.

F5 프로젝트별 레이아웃 바인딩 중간

뷰어 레이아웃(분할 여부, 각 분할의 탭과 활성 탭, 포커스, 비율, 세션 대화창 숨김)을 현재 프로젝트에 묶는다. 프로젝트(또는 그 아래 세션)를 클릭하면 그 프로젝트의 레이아웃이 통째로 돌아온다.

  • useViewerVM 은 layouts: Record<rootKey, Layout> 와 current: rootKey 를 가진다. rootKey 는 selection.root, 없으면 "".
  • App.tsx 에서 selection.root 가 바뀌면(이미 트리를 바꾸는 effect 가 있다) useViewerVM.switchProject(root) 를 부른다. 레이아웃이 없으면 빈 단일 분할·대화창 보임으로 만든다. 전환 직후 sessionHidden 에 맞춰 세션 패널을 접거나 편다(F1).
  • 프로젝트 A 에서 연 탭이 B 의 파일을 가리켜도 상관없다. 탭은 열린 시점의 현재 프로젝트 레이아웃에 속한다.
  • 전환 때 화면에서 내려간 탭의 상태: 편집 초안·스크롤(viewerBuffers)은 탭 키로 저장되므로 유지. 터미널 탭은 프로세스가 계속 돌고 xterm 인스턴스를 유지한다(§8 리스크 R2). 인터넷 탭 웹뷰는 숨긴다. 저장 안 한 편집이 있는 탭은 전환을 막지 않는다 — 돌아오면 그대로 있다.
  • 프로젝트를 닫으면(project_close) 그 레이아웃을 지운다. 기존 closeUnder(root) 가 이 역할로 바뀐다: 터미널 종료·웹뷰 제거 포함.
  • 프로젝트 선택이 null 이 되면(마지막 프로젝트 닫기 등) "" 레이아웃을 보인다.
수용 기준. ① A 에서 왼쪽 spec.docx · 오른쪽 Notion · 대화창 숨김, B 에서 단일 화면 design.md · 대화창 보임을 만들어 둔 뒤 A ↔ B 를 오가면 각자 그 모습 그대로다. ② A 의 Notion 로그인·스크롤이 B 에 다녀온 뒤에도 유지된다. ③ 앱을 다시 켜고 A 를 누르면 A 레이아웃, B 를 누르면 B 레이아웃이다. ④ A 를 닫으면 A 의 터미널 프로세스가 끝나고 settings.json 에서 A 레이아웃이 사라진다. ⑤ 1.0.1 의 settings.json(viewerTabs)을 가진 채 1.1.0 을 켜면 그 탭들이 사라지지 않고 경로가 속한 프로젝트 레이아웃으로 들어간다.

F6 터미널 클립보드 붙여넣기 작음 버그

터미널 탭(xterm.js)에서 클립보드의 글자가 Ctrl+V 로 붙지 않는다.

6.1 원인 분석

  • TerminalView.tsx 는 xterm 기본 설정만 쓴다. xterm.js 는 Ctrl+V 를 스스로 처리하지 않고 브라우저가 자기 숨은 textarea 에 paste 이벤트를 주기를 기다린다. 이 경로는 일반 브라우저에서는 동작하지만, Tauri(WebView2) 안에서는 paste 이벤트가 숨은 textarea 까지 오지 않거나 클립보드 읽기 권한이 없어 조용히 실패하는 사례가 보고되어 있다. 앱의 capability 는 core:default·dialog:allow-open 만 있고 클립보드 플러그인의 프론트 권한은 열려 있지 않다.
  • Windows 터미널 관례(Shift+Insert, 우클릭 = 붙여넣기, Ctrl+Shift+V)는 어느 것도 구현되어 있지 않다. 앱 루트가 onContextMenu 를 preventDefault 하므로 우클릭은 아무 일도 하지 않는다.
  • 반대 방향(선택 → Ctrl+C 복사)도 xterm 기본에서는 Ctrl+C 가 셸에 ^C 로 가므로 선택 복사가 안 된다.
이 세션에서는 GUI 를 띄워 재현하지 못했다. 위는 코드와 알려진 사례로 추정한 원인이며, 아래 해법은 원인이 어느 쪽이든 동작하도록 브라우저 paste 이벤트에 의존하지 않는 방식으로 잡았다.

6.2 해법

  • 붙여넣기는 백엔드가 클립보드를 읽는다. Rust 에 terminal_paste(id) 명령을 추가해, 이미 의존성에 있는 tauri-plugin-clipboard-manager(state.clipboard, 트리의 "경로 복사" 가 쓰는 것)로 텍스트를 읽어 그대로 돌려준다. 프론트는 받은 글자를 terminal.paste(text) 로 넣는다 — xterm 의 paste() 가 \n → \r 변환과 bracketed paste 모드를 처리하므로 terminal_write 에 직접 쓰지 않는다. 프론트 capability 변경 없음.
  • 키 가로채기. terminal.attachCustomKeyEventHandler 로 Ctrl+V, Ctrl+Shift+V, Shift+Insert(macOS 는 ⌘V) 를 잡아 terminal_paste 를 부르고 false 를 돌려 xterm·브라우저 기본 처리를 막는다.
  • 선택 복사. 같은 핸들러에서 Ctrl+C(macOS ⌘C) 는 terminal.hasSelection() 이면 terminal.getSelection() 을 terminal_copy(text)(백엔드 클립보드 쓰기)로 복사하고 선택을 지운다. 선택이 없으면 그대로 셸에 ^C 로 간다(인터럽트 유지). Ctrl+Shift+C 는 항상 복사.
  • 우클릭. 터미널 본문에서 우클릭하면 Windows Terminal 관례대로 선택이 있으면 복사, 없으면 붙여넣기. 컨텍스트 메뉴는 띄우지 않는다.
  • 포커스 보장: 탭이 활성화될 때 이미 terminal.focus() 를 부르고 있다. 분할(F2)·프로젝트 전환(F5) 뒤에도 같은 경로를 타도록 유지한다.
수용 기준. ① 메모장에서 두 줄을 복사해 PowerShell 터미널 탭에 Ctrl+V 하면 두 줄이 입력된다(두 번째 줄은 첫 줄 실행 뒤). ② Shift+Insert 와 우클릭(선택 없음)도 같다. ③ 출력 일부를 드래그로 선택하고 Ctrl+C 하면 클립보드에 들어가고 셸은 중단되지 않는다. ④ 선택 없이 Ctrl+C 하면 실행 중 명령이 중단된다. ⑤ git bash 탭에서 cat 을 띄운 뒤 붙여넣어도 글자가 깨지지 않는다(bracketed paste).

4. 상태 모델과 영속화

4.1 프론트 상태 (zustand, useViewerVM)

type PaneId = string;                         // uuid. 순서는 Layout.panes 배열이 정한다 (0 = 왼쪽)

type Pane = {
  id: PaneId;
  tabs: ViewerTab[];                          // 기존 ViewerTab 그대로 (+ web 필드)
  activeKey: string | null;
};

type Layout = {
  panes: Pane[];                              // 길이 1 또는 2
  focused: PaneId;
  ratio: number;                              // 왼쪽 분할 비율(%). 분할이 하나면 무시
  sessionHidden: boolean;                     // F1. 가운데 세션 대화창을 숨겼는가
};

type ViewerVM = {
  layouts: Record<string, Layout>;            // rootKey ("" = 프로젝트 없음) → 레이아웃
  current: string;                            // 현재 rootKey
  dragging: { pane: PaneId; key: string } | null;
  definitions: Definitions | null;            // 분할별로 옮길 수도 있으나 한 번에 하나만 뜨므로 전역 유지

  // 조회 도우미
  layout(): Layout;  pane(id): Pane | null;  findTab(key): { pane: Pane; tab: ViewerTab } | null;

  // 열기 — target 추가 (F3)
  open(request, extra?: Extra & { target?: "left" | "focused" | PaneId }): void;
  openDefault(path): Promise<void>;
  openWeb(url: string, paneId?: PaneId): Promise<void>;          // F4

  // 분할 (F2)
  focusPane(id): void;
  splitWith(key, side: "left" | "right"): void;                   // 분할 1→2, 또는 2개일 때 그 쪽으로 이동

6.1 P0 세부 — 기존 동작을 깨지 않는 선

  • tabKey·makeTab·confirmDiscard·closeTerminals·patchTab 은 그대로 두고 "어느 분할의 탭인가" 만 찾는 단계가 앞에 붙는다.
  • 저장 구독(startViewerEvents)은 layouts 가 바뀌면 300ms 뒤 전체를 저장한다. restored 플래그 규칙 유지.
  • 복원 중 AI 나 사용자가 먼저 연 탭은 지금처럼 복원된 목록 뒤에 붙인다 — 분할이 둘이면 왼쪽 분할 뒤에.
  • Rust 테스트: save_layouts 가 터미널 탭을 빼는지, restore_layouts 가 분할별로 없어진 파일을 걸러 active 를 맞추는지, 1.0.x viewer_tabs 마이그레이션이 프로젝트별로 나뉘고 "" 로 떨어지는지, 저장 뒤 viewer_tabs 가 비워지는지.

6.2 P5 세부 — 확인하며 진행할 것

  1. tauri = { version = "2", features = ["protocol-asset", "unstable"] } 로 바꾸고 Window::add_child(WebviewBuilder::new(label, WebviewUrl::External(url)), position, size) 가 Windows 에서 동작하는지 먼저 스파이크로 확인한다.
  2. WebviewBuilder::on_navigation 으로 스킴 제한. 새 창 요청 처리 API(on_new_window 등)는 현재 Tauri 버전에서 이름·지원 여부를 확인하고, 없으면 "새 창 링크는 외부 브라우저로" 로 대체한다.
  3. title 변경 이벤트가 없으면 on_page_load 에서 eval("document.title") 로 받는 대신 — 원격 페이지에 스크립트를 넣지 않는 원칙에 따라 — URL 호스트명만 쓴다.
  4. macOS 빌드는 CI(GitHub Actions)에서 컴파일만 확인 가능하다. 실행 확인은 사용자가 한다(§8 R1).
